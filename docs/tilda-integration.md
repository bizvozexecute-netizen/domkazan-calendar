## Безопасная последовательность в редакторе

1. После восстановления доступа открыть проект `12459815`, дублировать главную
   `70446131`, назвать копию «Каталог — тест DomKazan Calendar», задать отдельный
   тестовый URL. Убедиться, что копия не опубликована. Записать её page ID и ID
   скопированного блока T778: при копировании ID могут измениться.
2. Проверить, что HTML-блок HomeReserve находится именно на копии; отключить его
   только там. Не редактировать общие настройки проекта, header/footer, общий каталог
   товаров или шаблон страниц `/tproduct/`. Каталог товаров может быть общим у обеих
   страниц: копия страницы не является копией товарной базы.
3. Добавить на копию отдельный T123 перед каталогом из `tilda-catalog-test.html`.
   По умолчанию он выключен, не загружает скрипты/API и запрещает работу на исходной
   странице `70446131`. Это защита от ошибки установки, не средство авторизации.
4. Подготовить тестовый HTTPS API с разрешённым CORS для фактического origin
   предпросмотра. Не добавлять `*`. Если Tilda preview работает с другим origin,
   проверить его и использовать отдельное тестовое окружение; не ослаблять production CORS.
5. Сверить UID с домами тестовой БД, установить характеристики и тестовые тарифы,
   подтвердить mapping. В шаблоне заменить page/block ID, адрес API, политики и вставить
   проверенный массив в `config.mapping` (это исключает CORS-запрос к статическому JSON),
   только затем установить `enabled: true` в неопубликованной копии.
6. Проверить через предпросмотр Tilda. Если он не исполняет сторонний JS, понадобится
   отдельное согласование тестовой публикации/стенда. Самостоятельно ничего не публиковать.

## Устойчивая привязка

Карточка T778 генерируется как внешний `div[data-product-uid][data-product-url]`.
Внутри находятся отдельные ссылки изображения, текста и «Подробнее» (`#prodpopup`).
UID присутствует и в постоянном адресе `/tproduct/UID-slug`. Не использовать порядок,
название дома, CSS-классы, URL-суффикс названия или ID блока как идентификатор дома.
UID не переносится на новый товар автоматически: пересозданный товар надо сопоставить заново.

`public/embed/tilda-house-mapping.proposed.json` содержит все 64 публичных UID,
названия и ссылки, а также **предлагаемые**, ещё не подтверждённые `houseSlug` вида
`tilda-851186077552`. Они не импортированы в PostgreSQL и не означают существование
домов с такими slug. Если в БД уже есть дом, заменить `houseSlug` его существующим
уникальным `House.slug`, не создавать дубликат. После проверки установить
`confirmed: true` в отдельной утверждённой тестовой таблице. Не подключать эту таблицу
к демонстрационным домам `demo-house-*`: у них другая вместимость и тарифы.

Адаптер проверяет соответствие один-к-одному. Неизвестная или повторная карточка
приостанавливает поиск, сохраняет обычные ссылки и показывает предупреждение.
Обычный каталог без поиска не является подтверждением доступности по датам.

## Поведение адаптера

`domkazan-tilda.js` загружается после `domkazan-search.js`; вызов:

```js
const controller = DomKazanTilda.mount({
  root: document.getElementById("search-outside-catalog"),
  catalog: document.getElementById("rec-COPIED-CATALOG-ID"),
  apiUrl: "https://TEST-API/api/availability",
  privacyUrl: "https://TEST-POLICY",
  mapping: [{ productUid: "851186077552", houseSlug: "existing-house-slug" }],
  // Optional: separate controls using the API's district/bedrooms/amenities codes.
  filterRoot: document.getElementById("calendar-filters"),
  getFilters: () => ({ district: "", bedrooms: "", amenities: "" }),
});
```

`MutationObserver` ждёт карточки и отслеживает замену/перестановку при фильтрации,
пагинации и подгрузке. Он не вызывает внутренние функции Tilda и не зависит от её CSS.
При перерисовке, изменении UID или фильтров сбрасываются заявка и результат поиска;
введённые даты и гости сохраняются. Запоздавший ответ не восстанавливает старую заявку.
Для программных изменений фильтров вызывать `controller.invalidate()`.

После успешного GET `/api/availability` скрывается целая карточка, а не только ссылка.
Новая цена — **итого за выбранное число ночей**, внутри отдельного собственного
контейнера. Исходная статическая цена Tilda и цена в popup не изменяются: это
каталожные значения, их нельзя принимать за расчёт проживания. До включения на рабочем
сайте необходимо согласовать и проверить их обозначение/скрытие в реальном макете.
У кнопки заявки отдельная область вне ссылок; `click`/`pointerdown` не всплывают к
делегированным обработчикам каталога. Обычная ссылка «Подробнее» остаётся рабочей.
Данные карты и цена браузера не используются сервером как доверенные: заявка проходит
повторную серверную проверку занятости и расчёт стоимости.

Встроенные фильтры Tilda по бассейну/бильярду продолжают ограничивать карточки её
каталога. Дополнительные фильтры календаря передаются в API через `getFilters`.
Коды удобств должны совпадать с `House.amenities`; не выводить вместимость и тарифы
автоматически из описаний. Поиск и заявки используют тот же API и серверную валидацию,
что отдельное приложение. Описания и фотографии остаются в Tilda.

`controller.refresh()` вручную сверяет DOM, `invalidate()` требует новый поиск,
`destroy()` снимает observer/обработчики, удаляет добавленные области и восстанавливает
отображение карточек. У базового виджета добавлен `updateCards(cards)` для смены DOM.

## Проверки и условия продолжения

`npm test` включает пять тестов адаптера: динамическая загрузка, фильтрация/цена,
ссылки/кнопка, замена DOM и сброс заявки, запоздалый ответ, неизвестные/повторные UID.
Фикстуры сокращены и синтетические; HTML реальных домов не включён.

Перед включением нужны: доступ инструмента к сессии Tilda; непубликуемая копия;
доступный HTTPS тестовый API; подтверждённое соответствие UID данным БД и политика.
В браузере на настоящей копии ещё проверить desktop/mobile, popup/галерею,
пагинацию, очистку фильтров, пустую выдачу и сетевую ошибку, CORS, переходы назад,
раскладку без пустых промежутков и статические цены. В T778 могут быть разделители
рядов, которые нужно проверить визуально. Локальные DOM-тесты не подтверждают эти
свойства реального макета. Публикация и изменение рабочих страниц требуют отдельного согласования.
