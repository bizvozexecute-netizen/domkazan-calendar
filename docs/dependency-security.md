# Устранение пяти замечаний npm audit

Проверено 21 октября 2026. Все пять high-замечаний исходили из одной уязвимости
[GHSA-vfj7-8cjw-p6xm](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm)
в `braces <=3.0.3`; четыре остальных записи — зависимые пакеты:

`eslint-config-next → @next/eslint-plugin-next → fast-glob → micromatch → braces`.

На дату проверки исправленного опубликованного `braces` нет. Актуальный
`@next/eslint-plugin-next@16.4.2` по-прежнему зависит от `fast-glob@3.3.1`.
Обновление только `fast-glob` до 3.3.3 не удаляет `braces`. Предложенный npm
откат `eslint-config-next` до 14.2.35 несовместим с выбранной конфигурацией и
не применялся. Отключение правил ESLint или подавление advisory не используется.

## Решение

Сохранены установленные версии Next.js 16.4.0, React, Prisma 7.10.0, ESLint и
eslint-config-next 16.4.0. В `package.json` добавлена частная локальная
dev-зависимость под именем `fast-glob`, с собственным именем пакета
`@domkazan/next-eslint-glob`, и **только для `@next/eslint-plugin-next@16.4.0`**
применён override `$fast-glob`. Корневая ссылка нужна для воспроизводимого
разрешения file-зависимости в npm на Windows и Linux.

Это узкий адаптер для фактического вызова плагина:
`globSync(pattern, {onlyDirectories: true})`. Он делегирует поиск закреплённому
`tinyglobby@0.2.17`, уже используемому TypeScript ESLint в этом проекте.
[Документация tinyglobby](https://superchupu.dev/tinyglobby) описывает API и
отличия от fast-glob. Уязвимые `braces` и `micromatch` удалены из lockfile и
установленного дерева; исходники в node_modules не патчатся, install hooks нет.

Учтены различия: отключено рекурсивное раскрытие обычной папки, абсолютные пути
остаются абсолютными, завершающий `/` убирается с сохранением корня файловой
системы. Неожиданный API/options, длина шаблона более 4096 символов и вложенность
фигурных скобок более 64 отклоняются. Это не полная замена библиотеки fast-glob
для других потребителей.

## Проверка совместимости

`tests/lint-dependencies.test.mjs` входит в `npm test` и проверяет:

- исходную папку по умолчанию, относительные/абсолютные пути, обычную папку без
  захвата дочерних, glob/brace glob, массив корней, Windows-разделители,
  несуществующий путь и исключение файлов из поиска папок;
- работу настоящего правила `@next/next/no-html-link-for-pages` на временных
  проектах App Router и Pages Router, включая glob и массив корней;
- применение адаптера к проверенной версии плагина и единственному месту вызова;
- отклонение чрезмерно вложенного шаблона и неизвестных options;
- отсутствие `braces`/`micromatch` в lockfile и отсутствие новых потребителей
  fast-glob, которым мог бы не подойти ограниченный API.

Чистая установка проверяется через `npm ci`, затем TypeScript, ESLint, все
unit/DOM-тесты, интеграцию с временной PostgreSQL, Playwright и production build.
Оба аудита в CI теперь обязательны: прежний `continue-on-error` убран.
Dockerfile копирует локальный пакет перед установкой зависимостей.
При пересчёте lockfile на Windows нужно сохранять платформенные записи
`@emnapi/core`/`@emnapi/runtime`: npm может удалить их, хотя они требуются чистой
Linux-установке. Это контролируется тестом и обязательными CI/Docker-проверками.

## Сопровождение

При обновлении Next ESLint нужно перепроверить его glob API и диапазон override.
Версия указана точно намеренно: новый плагин не должен молча использовать старый
адаптер. После официального устранения цепочки удалить локальную dev-зависимость,
override и каталог `tooling/next-eslint-glob`, пересчитать lockfile и повторить
проверки. Контрольный тест версии заставит сделать это явно.

Эти изменения относятся к инструментам разработки. Деплой приложения, тестового
шлюза и изменение Tilda не требуются и в рамках исправления не выполняются.
