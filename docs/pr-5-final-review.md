# Финальное ревью PR #5

## Ревью после обновления тестового шлюза

Опубликованный UI `789fd68` повторно проверен без подмены скриптов: 6/6 сценариев
на desktop, mobile 390, 320 и WebKit iPhone, включая реальный Rutube. Просмотрены
снимки каталога и дома. Затем найдена и воспроизведена одна дополнительная P2:
при изменении тарифа между поиском и POST квитанция получала новую сумму, а
карточка, детализация и порядок сортировки оставались со старой стоимостью.

Исправление: актуальный итог из POST обновляет все видимые цены и состояние
выдачи; сортировка перестраивается без дополнительного запроса и прокрутки.
Старая детализация убирается: ответ POST подтверждает только итог и не возвращает
новый состав доплат. Форматирование, контакты, квитанция, запрет повторного
отправления и исходная точка возврата сохраняются. API/SQL/зависимости не меняются.

Два новых браузерных сценария проверяют расхождение и сортировку в семи
конфигурациях (14 проверок). Сквозной тест с PostgreSQL дополнительно проверяет
совпадение итоговой цены в БД, квитанции и блоке расчёта. Локально прошли
55 unit/DOM, 110 клиентских сценариев, TypeScript, ESLint, production build и
полный npm audit без уязвимостей; итоговые результаты CI фиксируются в PR.

Повторная живая проверка после публикации выявила ещё одну P2: в WebKit второй
кадр завис на загрузке CDN дольше 30 секунд, без сетевой ошибки и возможности
повтора. Отдельный повтор прошёл, но бесконечное ожидание в интерфейсе устранено.
Для обычного и увеличенного фото после 15 секунд появляется повтор загрузки;
новая попытка использует свежий URL того же изображения, чтобы не разделять
зависший запрос миниатюры. Tilda CDN принимает такой URL без перенаправления.
Старые таймеры и обработчики отключаются при смене фото, закрытии и уничтожении.
Сохранены клавиатура и фокус после повтора. Новая регрессия в семи конфигурациях
держит исходный запрос заблокированным, проверяет успешную новую попытку, затем
поздний ответ и отсутствие устаревшего индикатора. Живой тест допускает один
явный пользовательский повтор и отдельно сохраняет его счётчик; постоянная
ошибка CDN по-прежнему приводит к падению проверки.

Один дополнительный полный прогон с локальными скриптами внутри тестовой Tilda
создал одну синтетическую NEW-заявку через настоящий API и получил квитанцию.
Telegram-реквизиты в Preview отсутствуют; реальные контакты не использовались.
Повторная проверка доступности подтвердила, что заявка не закрыла даты.
Остальные живые прогоны — без POST. Точные SHA, deployment ID и результаты после
обновления только тестового шлюза указываются в описании PR; рабочий сайт и
production-приложение не публикуются, Draft и база PR сохраняются.

## Исправленные замечания

- **Переходы и возврат к поиску.** Открытие дома, возврат и история браузера
  переключают представление в том же документе, без повторной загрузки Tilda и
  появления её hero. До готовности показывается нейтральный статус. В записи
  истории сохраняются параметры исходного поиска, позиция и карточка для возврата
  фокуса. Изменение гостей/дат внутри дома не подменяет исходные результаты.
- **Стабильная привязка дома.** Поле Product UID существовало, но поиск, календарь
  и шлюз продолжали опираться на изменяемый slug. Теперь они используют UID;
  переименование внутреннего кода не скрывает доступный дом. Явное снятие
  привязки не допускает возврата к совпавшему slug другого дома. Миграции остаются
  совместимыми, первоначальный тестовый seed сохраняет UID новых домов и не
  перезаписывает правки владельца.
- **Стоимость принятой заявки.** Сервер пересчитывал цену, но клиент оставлял в
  квитанции итог старого поиска. Теперь итог берётся из ответа сервера и изменение
  цены явно обозначается. NEW-заявка не подтверждается и не закрывает даты.
- **Поздний change в WebKit.** Повторное событие фиксации того же значения после
  input/нажатия поиска могло отменить уже начатый расчёт. Одинаковые параметры
  не сбрасывают поиск; реальное изменение по-прежнему сразу отзывает старую заявку.

## Повторная проверка после исправлений

Дополнительно воспроизведены и исправлены пять замечаний:

- **[P2] Даты из повреждённой/старой ссылки.** Неверная строка вызывала
  `Invalid time value` при открытии календаря; дата далёкого будущего или прошлого
  уводила навигацию за доступный диапазон. Теперь календарь открывается в текущем
  месяце, если исходная дата некорректна либо недостижима в его диапазоне.
  Исходные условия не считаются валидными: серверный поиск разрешается только
  после выбора корректного периода. Первоначальный запрос календаря тоже
  использует безопасный месяц.
- **[P2] Новый поиск после возврата.** Сохранённая позиция восстанавливалась при
  каждом ответе API, поэтому новый поиск снова уводил пользователя к старой
  карточке. Восстановление теперь выполняется один раз при переходе; явный поиск
  показывает начало новой выдачи. Регрессия также повторяет «Назад/Вперёд» и
  проверяет сохранность фильтров, фокуса и отсутствие повторной загрузки Tilda.
- **[P2] Повторный seed после снятия привязки.** Одновременные переименование slug
  и снятие UID оставляли импортированный дом незаметным для seed. Попытка создать
  его заново конфликтовала с прежним первичным ID и останавливала сборку Preview.
  Поиск существующего тестового импорта теперь учитывает его стабильный ID.
  Интеграционный тест дважды запускает настоящий seed на отдельных фикстурах и
  проверяет неизменность полей, тарифов, ручных цен и закрытий.
- **[P2] Достоверность результата интеграционных тестов.** `status: null` при
  аварии/невозможности запустить дочерний процесс раньше превращался в код успеха.
  Теперь возвращается ошибка. Изолированный тест запускает настоящий runner с
  подменённой границей подпроцесса и проверяет успех, обычное падение, сигнал и
  ошибку запуска без обращения к БД.
- **[P2] Срок годности клиентских фикстур.** Часть DOM/браузерных тестов использовала
  даты 2–4 ноября 2026 года и переставала бы проходить после их наступления.
  Такие даты теперь задаются относительно дня запуска. Переход через Новый год
  проверяется на ближайшей границе, в пределах двухлетнего диапазона календаря;
  исправление повреждённой ссылки отдельно проверяется с выбором следующего месяца.

SQL-миграции и версии зависимостей при этой повторной проверке не менялись.
Оценка слияния относится к текущей базе PR `codex/vercel-preview`; состояние Draft
и целевая ветка сохраняются. После отдельного разрешения обновляется только
публичный тестовый шлюз; точные SHA и deployment ID указаны в PR. Основное
приложение остаётся на ранее проверенном Preview `e85cc33`; миграции и его
развёртывание при обновлении UI не выполняются. Исправления также проверяются
из ветки PR локально и во временном CI-окружении.

## Проверки

Новые регрессии проверяют переходы без загрузки документа, «Назад/Вперёд», точную
позицию и восстановление всех фильтров после изменения условий внутри дома.
PostgreSQL-тест проверяет переименование/снятие UID и совпавший чужой slug.
Сквозной браузерный тест использует настоящий API/БД с отличающимся внутренним
кодом и изменяет тариф между поиском и POST, проверяя цену в БД и квитанции.

Команды полной проверки:

```sh
npm ci
npm run db:generate
npm run typecheck
npm run lint
npm test
npm run test:integration
npm run build
npx playwright install --with-deps chromium webkit
npm run test:e2e
npm audit --omit=dev
npm audit
```

Интеграционные проверки требуют отдельного `TEST_DATABASE_URL` с суффиксом
`_test`; CI создаёт временную PostgreSQL. Контейнерный CI отдельно проверяет
миграции, HTTPS/proxy, отсутствие контактов в логах и восстановление архива в
новую базу. Результаты для текущего SHA фиксируются в описании PR.

Живой тест Tilda — opt-in, по умолчанию без отправки заявок:
`npx playwright test -c playwright.tilda.config.ts`. Он дополнительно считает
загрузки документа и проверяет отсутствие hero на каждом кадре после запуска
каталога. Внешний 502/недоступность CDN фиксируется отдельно от регрессии кода.

## Готовность и ограничения

Локальный стенд: `npm run local:up`, затем `https://localhost:8443/admin` и
`https://localhost:8443/test-catalog`; нужны Node 22.12+ и Docker Compose.
Подробности и восстановление: [testing.md](testing.md).

После успешного CI стенд подходит для тестовой приёмки на синтетических данных.
Перед внедрением нужны проверка владельцем тарифов/доплат и актуальной занятости,
действующая политика обработки данных и проверка физического iPhone/Safari.
WebKit-эмуляция не подтверждает поведение экранной клавиатуры и fullscreen на
устройстве. Доступность Rutube/CDN зависит от сторонних сервисов; все фотографии
каталога отдельно не проверялись. Первоначальная холодная загрузка страницы
Tilda с резервным каталогом остаётся отдельной от внутренних переходов.
Старый адаптер T778 использует явную таблицу соответствия из своего конфига;
текущая тестовая страница использует новый каталог с UID из БД.
