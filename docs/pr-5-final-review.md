# Финальное ревью PR #5

Проверяемая база: `codex/vercel-preview`, PR — `codex/tz-customer-ux`.
Рабочие страницы Tilda, общие товары и production-приложение не изменяются.
Обновляется только ранее разрешённый публичный тестовый шлюз; сервер приложения
остаётся в защищённом Preview. PR не объединяется.

## Исправленные замечания

- **Переходы и возврат к поиску.** Открытие дома, возврат и история браузера
  переключают представление в том же документе, без повторной загрузки Tilda и
  появления её hero. До готовности показывается нейтральный статус. В записи
  истории сохраняются параметры исходного поиска, позиция и карточка для возврата
  фокуса. Изменение гостей/дат внутри дома не подменяет исходные результаты.
- **Стабильная привязка дома.** Поле Product UID существовало, но поиск, календарь
  и шлюз продолжали опираться на изменяемый slug. Теперь они используют UID;
  переименование внутреннего кода не скрывает доступный дом. Явное снятие
  привязки не допускает возврата к совпавшему slug другого дома. Миграции остаются
  совместимыми, первоначальный тестовый seed сохраняет UID новых домов и не
  перезаписывает правки владельца.
- **Стоимость принятой заявки.** Сервер пересчитывал цену, но клиент оставлял в
  квитанции итог старого поиска. Теперь итог берётся из ответа сервера и изменение
  цены явно обозначается. NEW-заявка не подтверждается и не закрывает даты.
- **Поздний change в WebKit.** Повторное событие фиксации того же значения после
  input/нажатия поиска могло отменить уже начатый расчёт. Одинаковые параметры
  не сбрасывают поиск; реальное изменение по-прежнему сразу отзывает старую заявку.

## Проверки

Новые регрессии проверяют переходы без загрузки документа, «Назад/Вперёд», точную
позицию и восстановление всех фильтров после изменения условий внутри дома.
PostgreSQL-тест проверяет переименование/снятие UID и совпавший чужой slug.
Сквозной браузерный тест использует настоящий API/БД с отличающимся внутренним
кодом и изменяет тариф между поиском и POST, проверяя цену в БД и квитанции.

Команды полной проверки:

```sh
npm ci
npm run db:generate
npm run typecheck
npm run lint
npm test
npm run test:integration
npm run build
npx playwright install --with-deps chromium webkit
npm run test:e2e
npm audit --omit=dev
npm audit
```

Интеграционные проверки требуют отдельного `TEST_DATABASE_URL` с суффиксом
`_test`; CI создаёт временную PostgreSQL. Контейнерный CI отдельно проверяет
миграции, HTTPS/proxy, отсутствие контактов в логах и восстановление архива в
новую базу. Результаты для текущего SHA фиксируются в описании PR.

Живой тест Tilda — opt-in, по умолчанию без отправки заявок:
`npx playwright test -c playwright.tilda.config.ts`. Он дополнительно считает
загрузки документа и проверяет отсутствие hero на каждом кадре после запуска
каталога. Внешний 502/недоступность CDN фиксируется отдельно от регрессии кода.

## Готовность и ограничения

Локальный стенд: `npm run local:up`, затем `https://localhost:8443/admin` и
`https://localhost:8443/test-catalog`; нужны Node 22.12+ и Docker Compose.
Подробности и восстановление: [testing.md](testing.md).

После успешного CI стенд подходит для тестовой приёмки на синтетических данных.
Перед внедрением нужны проверка владельцем тарифов/доплат и актуальной занятости,
действующая политика обработки данных и проверка физического iPhone/Safari.
WebKit-эмуляция не подтверждает поведение экранной клавиатуры и fullscreen на
устройстве. Доступность Rutube/CDN зависит от сторонних сервисов; все фотографии
каталога отдельно не проверялись. Первоначальная холодная загрузка страницы
Tilda с резервным каталогом остаётся отдельной от внутренних переходов.
Старый адаптер T778 использует явную таблицу соответствия из своего конфига;
текущая тестовая страница использует новый каталог с UID из БД.
