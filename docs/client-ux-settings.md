# Заключительные UX-доработки и настройки владельца

Изменения подготовлены после приёмочного тестирования 23 октября 2026 года.
Рабочая главная Tilda, реальная база бронирований и VPN не изменяются.
PR сам не публикует приложение и не применяет миграции к внешней базе.

## Что редактирует владелец

| Где | Что можно изменить | Ограничения |
| --- | --- | --- |
| Tilda, существующий каталог | Фотографии, порядок галереи, описания, особенности и правила дома, публичное название, ссылка на существующее Rutube-видео | Контент остаётся в прежнем каталоге. При изменении структуры блоков или формата ссылки видео нужен разработчик. |
| Админка → Дома | Идентификатор и привязка к Tilda UID, внутреннее название, вместимость, район, спальни, санузлы, удобства, включение в поиск | Публичный контент берётся из Tilda; изменение внутреннего названия не переименовывает карточку на Tilda. Для фильтрации важны данные нашей базы, а не только текст описания. |
| Админка → Шахматка / тарифы | Базовые тарифы, периоды, ручные цены, закрытие дат | Текст цены на Tilda не заменяет серверный расчёт. Ручные исключения и подтверждённые брони сохраняют прежние правила. |
| Админка → Заявки | Статусы и ручное подтверждение после оплаты | Отправка заявки сама по себе не подтверждает бронь и не закрывает даты. |
| Админка → Настройки | Основной цвет кнопок/ссылок, основной цвет текста, фон каталога | Формат `#RRGGBB`. Контраст основного цвета и текста с белым и фоном ≥ 4.5:1; неподходящие сочетания нельзя сохранить. |
| Админка → Настройки | Заголовок каталога, заголовок проверки стоимости, заголовок формы заявки | Обычный текст, до 240 символов. |
| Админка → Настройки | Подписи поиска, расчёта, открытия/отправки заявки, видео, звонка, Telegram, WhatsApp | До 40 символов; адреса и номера контактов здесь не меняются. |
| Админка → Настройки | Общая ошибка поиска, ошибка данных заявки, текст успешного получения заявки, сообщения о занятых датах, отсутствии тарифа и других неподходящих условиях | До 240 символов. HTML, CSS, JS, произвольные поля и управляющие символы запрещены. Юридическое согласие и предупреждение, что заявка не подтверждает бронь, не редактируются. |

Сначала измените поля и посмотрите предпросмотр цветов. Затем нажмите
«Сохранить настройки». Кнопка «Подставить стандартные значения» только заполняет
форму — для применения также требуется сохранение. Результат показывается
в форме; при сетевом сбое введённые значения остаются на месте.

При конфликте двух администраторов сервер возвращает 409, не перезаписывая
чужие изменения. Скопируйте нужный текст и обновите страницу перед новой попыткой.
Настройки применяются при следующем открытии каталога, без публикации Tilda
или изменения JavaScript. Уже открытая форма заявки не пересоздаётся ради настройки.

## Что требует разработчика

- Вёрстка, структура страниц, шрифты, логотип, иконки, новые блоки и фильтры.
- Добавление новых редактируемых текстов и семантических цветов ошибок/состояний.
- Контактные адреса/номера, URL политики и юридические формулировки.
- Алгоритмы расчёта, ограничения периода/гостей, правила подтверждения и безопасность.
- Telegram, инфраструктура, домены, интеграционные ключи и развёртывание.
- Изменение стабильных page/block/Product UID и подключения на рабочую Tilda.

Это небольшой раздел настроек, не визуальный конструктор и не вторая CMS.

## Кнопки и календарь

Primary — заливка основным цветом, белый текст. Secondary — белый фон,
основной цвет текста и заметная рамка. Видео и основные кнопки имеют единые
стили, контакты используют secondary. Минимальная высота ключевых действий
48 px; дни календаря и переключение месяцев — 44 px. Длинные подписи
переносятся без горизонтального скролла, есть видимый фокус клавиатуры.

Раньше стиль disabled перекрывал выбранный заезд, а в WebKit дополнительно
мешал hover. Теперь aria-pressed/выделение выбранной даты имеют приоритет
и при наведении. Выбор той же или более ранней даты начинает диапазон заново;
последующий выезд выделяет весь диапазон, включая границы. Выбор сохраняется
при смене месяца и повторном открытии. Нельзя пересекать занятую ночь или
ночь без тарифа; старые правила минимального проживания не отключены.

## Причины недоступности конкретного дома

Публичный `/api/availability` сохраняет прежний `houses`; для пустого результата
с параметром `house` дополнительно возвращает `unavailability`:

- `CAPACITY` и `maxGuests`: точная максимальная вместимость из PostgreSQL.
- `OCCUPIED`: есть пересечение закрытого периода или подтверждённой заявки.
- `UNPRICED`: хотя бы на одну ночь нет ни тарифа, ни ручной цены.
- `MIN_NIGHTS` и `minNights`: период короче действующего минимума.
- `UNAVAILABLE` / `CONDITIONS`: дом отключён/не найден либо не подходят иные фильтры.

При нескольких ограничениях приоритет: вместимость → занятость → отсутствующий
тариф → минимум ночей → прочие условия. Для общего каталога причины каждого
скрытого дома не раскрываются. Идентификаторы заявок, контакты, причины ручных
блокировок и технические ошибки в диагностические ответы не попадают.
Ошибки поиска и формы не выводят произвольный `error` из ответа API.

Это объяснение результата поиска, а не гарантия бронирования: существующая
повторная серверная проверка при заявке/подтверждении и защита от конкурентной
брони не меняются.

## Хранение и применение

- `ClientUiSettings`: одна JSONB-запись `public`, положительная revision,
  optimistic locking. Миграция добавляет только новую таблицу, не меняя дома,
  тарифы, заявки или действующие ограничения.
- `GET/PUT /api/admin/settings`: сессия администратора; для записи также
  проверяется Origin, тело ограничено 16 КБ и строгой схемой.
- `/admin/settings`: существующий защищённый layout админки.
- `GET /api/client-settings`: только разрешённые цвета и тексты, `no-store`,
  CORS только настроенного Tilda origin. Ни внутренних ревизий, ни секретов.
- Тестовый шлюз проксирует только публичный GET. Административный маршрут через
  шлюз не открывается.
- Настройки запрашиваются параллельно с каталогом. При недоступности/некорректном
  ответе либо ожидании больше 1 секунды используются проверенные стандартные
  значения. В этом случае новые тексты/цвета появятся при следующем успешном
  открытии; поиск не блокируется из-за настроек.
- Повторная клиентская проверка цветов и plain text не заменяет серверную
  валидацию. Стандартные значения JSON и встроенный JS сверяются тестом.
- Фон также проверяется с фиксированным цветом вспомогательных подписей:
  контраст ≥4.5:1. Поэтому средние/тёмные фоны, ухудшающие их читаемость,
  сохранить нельзя. Это настройка светлого интерфейса, не переключатель темы.

## Проверка и внедрение

```sh
npm ci
npm run db:generate
npm run typecheck
npm run lint
npm test
npm run test:integration
npm run build
npm run test:e2e
npm audit
```

Интеграционный и полный браузерный runner требуют отдельный `TEST_DATABASE_URL`,
имя БД заканчивается на `_test`, URL отличается от `DATABASE_URL`. CI использует
временную PostgreSQL. Тесты настроек содержат только синтетические данные.
В CI проверяются миграция, авторизация/Origin, параллельные сохранения, публичный
ответ, причины отказа, работа формы админки и регрессии клиентского пути.

Для отдельного разрешённого обновления тестового стенда: сначала применить
новую миграцию **к тестовой БД**, затем выпустить тестовый Preview и шлюз с
новым `/api/client-settings` и синхронными JS-зеркалами. T123 остаётся прежним.
Проверить `/admin/settings`, публичные настройки, поиск и клиентский путь.
Публикация рабочей Tilda и миграция реальной БД в этот PR не входят.

Chrome и WebKit iPhone в Playwright проверяют выделение первой даты и диапазона,
смену месяца, повторный выбор, контраст/размеры действий, настройки во вложенных
Shadow DOM, все причины отказа и безопасный отказ API. Это эмуляция движка
мобильного Safari; физический iPhone перед внедрением рекомендуется проверить
отдельно. Синтетический iframe видео проверяет контракт UI, не реальную сеть Rutube.
