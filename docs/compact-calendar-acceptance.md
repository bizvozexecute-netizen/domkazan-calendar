# Финальная приёмка UX от 25.10.2026

Рабочая база ветки: `codex/vercel-preview`. Изменения предназначены для отдельного
PR и тестовых Preview/шлюза. Рабочая Tilda, основной production и VPN не входят
в обновление. Миграций и изменений бизнес-логики нет.

## Шахматка

- На телефоне до 760 px всегда компактный режим, переключатель «Вид» и пояснения
  скрыты. Сохранённый ранее обычный режим не влияет на мобильную таблицу.
  На компьютере переключатель остаётся; выбор сохраняется локально в браузере
  (`domkazan.calendar-density.v1`) и восстанавливается при возврате на широкий экран.
  При запрете storage режим работает до закрытия страницы.
- Мобильный поиск занимает одну строку. Навигация по месяцам находится внутри
  scroll-контейнера и закреплена сверху и слева; заголовки дат закрепляются ниже
  неё с учётом `safe-area-inset-top`. Панель не перекрывает даты, колонка домов
  сохраняет закрепление. Высота области ограничена динамическим и малым viewport
  (`dvh`/`svh`), чтобы учитывать панели мобильного браузера. Обработчиков прокрутки
  страницы или изменения React-состояния при прокрутке не добавлено.
- Компактные строки 32 px, даты от 30–32 px, колонка домов 40/64 px на телефоне
  и 96 px на компьютере. Крупные элементы управления вне сетки остаются 44 px.
  Это осознанный компромисс плотности: обычный режим на компьютере сохраняет
  ячейки от 64×44 px.
- На телефоне ориентир 8–10 дат с обычной пятизначной ценой. На большом экране
  таблица растягивается до ширины контейнера, чтобы показать весь месяц.
  Длинные цены автоматически расширяют даты: число целиком важнее числа колонок.
  Сокращений «тыс.», округления копеек и обрезания цены нет.
- Название можно открыть нажатием/Enter/Space; доступный нативный диалог содержит
  полное название и ссылку редактирования, поддерживает Escape и возврат фокуса.
- При выборе первой даты мобильная панель остаётся компактной и не перекрывает
  выбор второй. Для одной даты есть отдельная кнопка раскрытия действий.
- Цветной заголовок только у пятницы и субботы. Воскресенье обычное. Сегодня
  дополнительно отмечено нижней линией; тарифные правила не менялись.

## Прокрутка и производительность

Один scroll-контейнер сохраняет нативные sticky-заголовки/колонку. Используются
`touch-action: pan-x pan-y pinch-zoom`, `overscroll-behavior: contain` только внутри
сетки и `overflow-anchor: none`. Страница за пределами таблицы прокручивается
обычно. Pinch zoom, wheel и клавиатура не блокируются.

CSS не предоставляет динамической фиксации преимущественной оси жеста;
изменение touch-action после начала жеста не действует ([MDN touch-action](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/touch-action)).
`overscroll-behavior` управляет передачей прокрутки на границах, а не направлением
жеста ([MDN overscroll-behavior](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/overscroll-behavior)).
Поэтому маленький пассивный обработчик определяет ось после 8 px и удерживает
только второстепенную координату до конца инерции. Нет `preventDefault`, захвата
pointer, обработчиков на document и обновления React при прокрутке. Направление
сбрасывается для нового жеста, двух пальцев, wheel и клавиатуры.

Строки мемоизированы: выбор затрагивает текущую/предыдущую строку, ввод цены
не перерисовывает все ячейки. Тест на 80 домах/31 дне записывает размеры, интервалы
кадров, дрейф осей и число DOM-изменений при прокрутке. Виртуализация не добавлена:
сначала измерения, а не усложнение выделения/доступности.

## Клиентский интерфейс и окружения

- Телефон чёрный/белый в карточке, шапке и подтверждении заявки. Hover, active и
  клавиатурный focus различимы; `tel:` и безопасная нормализация не менялись.
- `/api/client-settings` возвращает безопасный `testEnvironment`: true для
  `TEST_CATALOG_ENABLED=true` или Vercel Preview. Клиент не может убрать маркировку
  тестового Preview параметром виджета. Тестовый bootstrap остаётся `testMode:true`.
- Для будущего согласованного production-подключения нужны одновременно
  нетестовое серверное окружение и явный `testMode:false`. Тогда тестовые пояснения
  и суффикс заголовка вкладки скрыты. Текущие окружения не переключаются.
- До отдельного согласования реальных домов, цен и занятости production запрещён.

## Проверки

Новые автоматические сценарии: Chrome desktop, Chromium Android 320/375/390/430,
WebKit desktop/iPhone 390 и узкий WebKit iPhone 320. Временная PostgreSQL нужна
для настоящих закрытия/открытия, ручной цены и проверки публичного поиска.
Синтетические дома удаляются после каждого сценария.

Playwright проверяет обе оси, sticky, плотность, полное название, запоминание
режима, диапазон, подтверждение массовых операций, позицию после сохранения,
длинные цены и отсутствие переполнения страницы. Для Chromium дополнительно
выполняются нативные touch-жесты через CDP; синтетические TouchEvent отдельно
проверяют пассивный fallback. Эмуляция WebKit не заменяет ручной прогон пальцем
на физическом iPhone/Android перед production.

Полный CI: TypeScript, ESLint, unit, PostgreSQL integration, production build,
Playwright, контейнеры/proxy/seed/backup/restore и оба npm audit. Фактические
результаты и адреса тестового обновления фиксируются в PR после проверок.
