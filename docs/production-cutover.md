## Выпуск сервера

Для Nginx теперь используется `ops/server/render-nginx.py`, его нужно копировать
в `/srv/domkazan/operations/` вместе с шаблоном и `deploy.sh`.
Отсутствующие флаги сохраняют прежнее поведение: только админка.

`PUBLIC_CATALOG_ENABLED=true` в защищённом `app.env` открывает только публичное
чтение `/api/catalog`, `/api/client-settings`, `/api/availability`,
`/api/house-calendar` и статические `/embed/`. Сами API задают CORS для
`TILDA_ORIGIN`, код виджета разрешён для `https://domkazan116.ru`.
Административные API сохраняют авторизацию и проверку источника.
`/api/internal/`, тестовые страницы и прочие маршруты извне закрыты.

`PUBLIC_REQUESTS_ENABLED=true` отдельно открывает `/api/requests`.
Рендерер не разрешит этот флаг без включённого каталога и настроенного HTTPS
`PRIVACY_POLICY_URL`. Это техническая проверка адреса, а не проверка содержания
документа или юридической готовности. Не подключать частный черновик как политику.

Перед выпуском: резервная копия БД и конфигурации, тест Nginx, затем reload,
проверка HTTPS и маршрутов. PostgreSQL остаётся во внутренней Docker-сети без
внешнего порта. Прокси подставляет настоящий IP и закрытый секрет, очищает
входящие поддельные proxy-заголовки. Логи доступа выключены.

## Выпуск Tilda

```sh
node scripts/render-tilda-production-snippet.mjs https://45.147.31.241/privacy-2026-10-26.html
```

Полученный `integration/tilda-70446131-t123.html` предназначен для **замены**
содержимого существующего T123 `rec1184803096` с HomeReserve. Не добавлять рядом
ещё один работающий календарь. Скрипт ограничен главной страницей `/`, ID
`70446131` и этим блоком. Меню `rec1088252761` и обложка `rec1096886496`
сохраняются в каталоге и скрываются при открытии дома. Старый каталог
`rec4148990801` возвращается при отказе загрузки. Исходные товары не меняются.

Перед заменой дополнительно сохранить исходный HTML T123: копирование страницы
Tilda меняет ID блоков, а встроенный HTML может сохранять старые CSS-селекторы.
Для отката надёжнее вернуть исходный T123 на исходной странице и опубликовать
только её. Сохранить исходные настройки и прежнюю публикацию.

Скрипт указывает рабочий сервер, `testMode:false`, версию политики
`/privacy-2026-10-26.html` и отдельное согласие `/consent-2026-10-26.html`.
Файлы из `public/` размещаются также в `/var/www/domkazan/` с правами 0644;
родительская папка 0755. Nginx разрешает только эти два точных имени и запрещает
исполнение скриптов через CSP. `/privacy` перенаправляет на действующую редакцию.
До включения формы оба документа должны отвечать HTTP 200 по HTTPS. При выпуске
новой редакции использовать новое имя: не перезаписывать старый текст, ссылка на
который уже сохранена в заявках. Тестовые предупреждения остаются на тестовом стенде.

Пользователь подтвердил для публикации имя оператора «ИП Иванов Иван Иванович»
и телефон +7 905 310-66-05, отказался от email. Дополнительные регистрационные
реквизиты и адрес не выдуманы. Документ описывает приём заявок и ручную обработку
обращений, а не подтверждает полноту организационных мер оператора. Размещение
сервера, уведомления регулятору и выполнение сроков удаления должен проверить
оператор по своим фактическим условиям; они не подтверждены публикацией HTML.
Основа структуры: 152-ФЗ, статьи 9 и 18.1,
https://mintrud.gov.ru/docs/laws/130 .

Передача содержимого заявок в Telegram в опубликованной редакции не подключена.
Добавление бота требует проверки условий передачи, новой редакции документов и
отдельного разбора старой очереди: новая редакция не меняет прежние согласия задним
числом. Отсутствие бота не теряет заявку: она остаётся в админке, outbox ожидает.

При отказе ресурсов рабочий bootstrap меняет только старые ссылки карточек
`/calendar-test-*` на существующий публичный телефон. Это не направляет реального
клиента в тестовую форму. Остальные ссылки Tilda сохраняются.

## До публичного переключения

1. Проверить подтверждённые сведения оператора, фактическое размещение данных,
   сроки хранения и подключённые сервисы. Email по решению пользователя не используется.
2. Разместить согласованный документ, подключить его к форме и проверить согласие.
3. При необходимости подключить Telegram отдельно после обновления документов.
   Настоящие Bot/Chat ID хранить в защищённом окружении, периодическую доставку
   выполнять с `TELEGRAM_RETRY_SECRET`. Не присылать токен в чат или PR.
4. Проверить рабочий сервер из браузера Tilda: контент, цены из БД, недоступные и
   неподготовленные дома, контакты, форма и вход в админку на двух устройствах.
5. Сохранить владельцу доступ для заполнения тарифов и занятости. Отключённые или
   неоценённые дома не считать свободными. Не включать все дома массово ради выдачи.
6. Публиковать только согласованную главную. Не использовать «Опубликовать все».

## Проверки подготовки

Добавлены проверки раздельного открытия публичного чтения и формы, строгих
маршрутов, CORS, proxy-заголовков и отказа при неверных настройках. Playwright
проверяет привязку рабочей страницы, отсутствие тестовой маркировки при рабочей
конфигурации, переход в дом и возврат с числом гостей, восстановление прежнего
каталога при отказе ресурсов. Фикстуры не заменяют проверку фактической публикации.
