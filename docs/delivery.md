# Передача DomKazan Calendar

## Согласованный результат

Основание: переписка с Виталием 1–3 октября 2026. Выбран вариант доработки Tilda.
Владелец продолжает менять названия, фотографии, описания и добавлять объекты в Tilda.
Отдельная система хранит занятость и цены. Оплата и подтверждение заезда остаются ручными.

| Требование | Реализация |
| --- | --- |
| Собственный календарь вместо подписки на модуль | PostgreSQL, закрытая админка, независимый API |
| Дома слева, даты сверху, цена в ячейке | `/admin`, поиск дома, выбор одной даты или диапазона |
| Четыре базовые цены | Будни, пятница, суббота, воскресенье на странице дома в админке |
| Праздники и закрытие дат | Ручная цена, закрыть/открыть диапазон в шахматке |
| Даты и ввод числа гостей на сайте | Виджет на тестовой странице Tilda |
| Свободные дома с итоговой ценой и фильтрами | Список/плитка, название, бюджет за заезд, спальни, удобства, сортировка |
| Отдельная страница дома без попапа | Собственный URL `?house=<Product UID>` на той же странице Tilda; ссылка открывается в новой вкладке, даты переносятся |
| Сохранить редактирование контента в Tilda | Публичный каталог читается раз в минуту; изображения остаются на CDN Tilda |
| Добавление объекта без повторного ввода контента | «Добавить новые дома из Tilda» в админке; новый дом сначала скрыт, тарифы и вместимость проверяет владелец |
| Заявка и связь с владельцем | Заявка сохраняется в админке, Telegram outbox; кнопки телефона и мессенджеров на странице дома |
| Без автоматической оплаты и брони | Новая заявка не закрывает даты, подтверждение выполняется вручную |

Отдельные страницы используют query URL и один редактируемый шаблон. Это самостоятельные
представления домов, а не всплывающие окна и не 63 независимых Tilda-лендинга.
Индивидуальные лендинги владельца можно продолжать создавать отдельно в Tilda.

## Что доступно на стенде

Каталог: https://domkazan116.ru/calendar-test-311744409

Пример дома: https://domkazan116.ru/calendar-test-311744409?house=555240345232

Фото и тексты публичного каталога настоящие. Занятость и расчёт на стенде тестовые.
Тарифы импортированы из опубликованных описаний; смысл доплат, сезонные цены, минимальное
проживание, обязательные услуги и фактические брони требуют подтверждения владельцем.
Не переносить тестовую БД в рабочую среду как достоверную занятость.

В тестовой форме автоматически подставляются «Тестовый Гость» и `+70000000000`;
галочку согласия тестировщик ставит сам. Шлюз и Preview отвергают другие контакты.
Telegram-бот к стенду не подключён. Обычные контактные ссылки ведут к опубликованным
контактам владельца, автоматически сообщения не отправляются.

## Демонстрация заказчику: 5 минут

1. Открыть каталог, выбрать даты и вписать число гостей. Показать результат и итог за заезд.
2. Включить бассейн/баню, выбрать спальни или бюджет, повторить поиск.
3. Открыть дом в новой вкладке: фотографии, условия, выбранные даты, цена, связь с владельцем.
4. В админке выбрать тот же дом и закрыть выбранные даты. Повторить поиск: дом исчезает.
5. Открыть даты и задать ручную цену. Повторить поиск: цена меняется. Затем показать четыре
   базовых тарифа на странице редактирования дома.
6. Отправить тестовую заявку, показать её в админке. Убедиться, что новая заявка не закрыла даты.
7. Вернуть изменённые для показа тарифы и даты к состоянию до демонстрации.

Доступ в админку передаётся приватно, данные входа не включаются в Git или этот документ.
Защищённая Vercel Preview дополнительно требует входа в разрешённый аккаунт Vercel.

## До перехода на рабочий сайт

Нужны от владельца:

1. Выгрузка занятых дат **без имён, телефонов и оплаты**: Product UID/название дома, заезд, выезд.
   Либо владелец самостоятельно закрывает все текущие брони в шахматке.
2. Проверка вместимости и тарифов каждого дома, доплат за гостей за ночь, разовых сборов,
   минимального проживания, праздников и специальных правил (в том числе взрослые/дети).
3. Telegram-бот и чат для заявок. Токен вводится владельцем в защищённые переменные среды;
   не отправлять его в переписку. Перед включением сделать одну согласованную тестовую отправку.
4. Утверждённая политика обработки данных и подтверждение публичных контактных ссылок.
5. Выбор отдельного рабочего хостинга/БД и подтверждение переключения основной страницы.

Техническая последовательность переключения:

1. Создать отдельную рабочую БД, случайные секреты, админ-учётную запись; применить миграции.
   Не запускать тестовые seed-скрипты. Зафиксировать резервную копию и проверить восстановление.
2. Выставить `APP_ORIGIN`, `TILDA_ORIGIN=https://domkazan116.ru`, `PRIVACY_POLICY_URL`,
   `PUBLIC_OWNER_PHONE`, `PUBLIC_OWNER_TELEGRAM`, `PUBLIC_OWNER_WHATSAPP`, параметры Telegram
   и доверенного proxy. `TEST_CATALOG_ENABLED` выключен, тестовый шлюз не используется.
3. Через админку импортировать объекты из Tilda. Заполнить тарифы, закрыть текущие брони,
   проверить цены и даты с владельцем. Сверка всегда предшествует включению дома в поиск.
4. Рабочий T123 загружает `domkazan-search.js` и `domkazan-catalog.js` с рабочего API origin,
   вызывает `DomKazanCatalog.mount({root, apiOrigin, privacyUrl, pagePath, testMode:false})`.
   `privacyUrl` должен точно совпадать с серверным `PRIVACY_POLICY_URL`.
   Включение и скрытие прежних блоков ограничить точными ID согласованной страницы/блока.
5. До публикации проверить полный сценарий и реальную доставку согласованной заявки.
   Для Vercel обеспечить повторную доставку outbox планировщиком; Compose включает worker.
6. По отдельному разрешению переключить основную страницу. Старый модуль сохранить выключенным
   для отката. До этого момента текущий модуль обслуживает посетителей как раньше.

## Проверки

`npm test`, `npm run typecheck`, `npm run lint`, `npm run build` проверяют модуль и сборку.
GitHub Actions дополнительно проверяет миграции, PostgreSQL, приложение в Docker, backup/restore
и браузерные сценарии desktop/mobile. `tests/e2e/catalog.spec.ts` соединяет новую выдачу
с настоящей тестовой БД: доплата/сбор → заявка/outbox → ручная цена → закрытие дат → исключение
из выдачи. Подменяется только ответ публичного каталога Tilda, а не API занятости и заявок.
Скриншоты `catalog.png` и `house.png` сохраняются в артефакт CI.
