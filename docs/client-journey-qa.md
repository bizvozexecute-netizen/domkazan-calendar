# Приёмка клиентского пути, 21 октября 2026

Проверяемый путь: тестовая Tilda → каталог/поиск → API занятости и серверный расчёт → страница дома/медиа → заявка → PostgreSQL → локальная квитанция/возврат. Подтверждение и закрытие дат проверяются отдельно в CI с временной PostgreSQL, без реальных клиентов и Telegram.

## Исправления по результатам прохода

| Проблема | Результат |
|---|---|
| На телефоне длинное описание отодвигало расчёт далеко вниз | Блок дат/цены/заявки идёт сразу после галереи, перед описанием; DOM-порядок совпадает с мобильным порядком |
| При задержке CDN показывалось частично загруженное фото без пояснения | Статус загрузки, показ целого фото после загрузки, понятная ошибка и повторная загрузка |
| Увеличенное фото нельзя было листать; активная миниатюра уходила за край | Кнопки/стрелки внутри увеличения, циклический переход по фото, видимая активная миниатюра, возврат фокуса |
| Горизонтальный свайп мог закончиться открытием увеличения | Подавление завершающего click и проверка направления жеста; вертикальная прокрутка сохраняется |
| Сбой iframe оставлял пользователя без альтернативы | Постоянная безопасная ссылка на исходный Rutube рядом с видео; без autoplay; выход на фото удаляет iframe |
| Ошибка загрузки каталога соседствовала с вечным «Загружаем…» | Тайм-аут, замена загрузки понятным сообщением и повторная загрузка |
| Зависший POST мог бесконечно блокировать форму | Тайм-аут 15 секунд и явное действие «Повторить эту же заявку» |
| После неопределённой ошибки контакты можно было редактировать, хотя повторялся прежний payload | Контакты зафиксированы, повтор использует исходные данные и idempotency key; карточка не создаёт новый ключ |
| Успех старой отправки после смены параметров оставался незаметным | Сообщение о принятой заявке для прежних параметров; новая форма не получает старую квитанцию |
| Конфликт занятости оставлял устаревшую заявку | Форма и действие сбрасываются, требуется новый поиск |
| Открытие дома и возврат заново загружали Tilda: мелькал hero, затем страница прокручивалась | Переходы внутри того же документа, нейтральный экран до готовности представления, восстановление позиции и фокуса на карточке; работают «Назад/Вперёд» браузера |

При возврате сохраняются даты, гости, удобства и сортировка исходного поиска, даже если условия затем менялись в доме. Позиция и карточка записываются в соответствующую запись истории браузера; sessionStorage нужен только как дополнительное восстановление после перезагрузки. Контент каталога переиспользуется в пределах посещения, а доступность и стоимость повторно проверяются API. Проверки Playwright контролируют одну загрузку документа, отсутствие hero после запуска каталога, точную позицию возврата и восстановление фильтров. На опубликованной тестовой странице это дополнительно проверяется на каждом кадре перехода. Первоначальная загрузка документа с резервным каталогом Tilda остаётся отдельным этапом; рабочая страница и её hero не изменяются.

Фотографии, полные описания, ссылки на фильмы и публичные контакты остаются из существующего каталога Tilda. Рабочие страницы и общие товары не редактируются.

## Автоматические проверки

- Основной набор: `npm run typecheck`, `npm run lint`, `npm test`, `npm run test:integration`, `npm run build`, `npm run test:e2e`.
- В Playwright добавлены Chrome: desktop, 320/375/390/430; WebKit: desktop и iPhone 13. Это эмуляция движка/размеров, не физический iPhone.
- Изолированные сценарии: полный путь, сортировка без нового запроса, возврат с параметрами, длинное описание, галерея/клавиатура/жесты, ошибка CDN, ошибка каталога/повтор, неизвестный дом, ошибка/гонка поиска, согласие, повтор/тайм-аут заявки, смена параметров во время POST, конфликт дат, корректная граница выезда на занятую ночь.
- Сценарии с настоящим API и временной PostgreSQL проверяют сохранение NEW-заявки/уведомления, изменение цен/занятости из админки и ручное подтверждение. Закрытие/подтверждение выполняется только на вымышленных домах в CI.
- Видео сценариев записывается только для публичного пути с синтетическими контактами. Тесты входа администратора не записывают видео/trace.

## Настоящая тестовая Tilda

Отдельный opt-in набор не входит в CI и обращается только к `/calendar-test-311744409`:

```sh
npx playwright install webkit
npx playwright test -c playwright.tilda.config.ts
```

Требуется установленный Google Chrome. По умолчанию POST заявки запрещён самим тестом. Для одной синтетической NEW-заявки только в desktop-сценарии можно явно установить `LIVE_TILDA_ALLOW_SYNTHETIC_REQUEST=true`. Имя и номер проверяются до отправки: «Тестовый Гость», `+70000000000`. Реальные данные не вводятся; Telegram в тестовом окружении отключён. Повтор запуска с этим флагом создаст ещё одну тестовую заявку, поэтому флаг нужен только при ручной приёмке.

Набор использует реальные Tilda-фото и существующий ролик «Щербаковка 3». Проверка видео требует `paused === false` и продвижения `currentTime` после пользовательского нажатия; iframe-заглушка в изолированных тестах не считается доказательством воспроизведения. Переключение на фото удаляет реальный плеер.

Скриншоты, записи и JSON-доказательство воспроизведения сохраняются локально в игнорируемую `.local-design-review/live-results`. Они не содержат паролей администратора. На момент проверки источник отдавал 63 дома, 1087 фото и 12 Rutube-ссылок. Это инвентаризация, а не утверждение о ручном просмотре каждого фото и всех роликов.

## Границы приёмки

WebKit не заменяет физический Safari/iOS. Нужна заключительная проверка реального iPhone: клавиатура, safe area, полноэкранное видео, сворачивание/возврат браузера. Сторонний Rutube/CDN и холодный запуск API могут менять задержки; резервная ссылка не гарантирует доступность стороннего сервиса. Прежняя dev-only цепочка ESLint впоследствии [устранена без понижения основных пакетов](dependency-security.md); оба аудита обязательны в CI. Production-приложение не публикуется, PR не объединяется.
