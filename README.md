# DomKazan Calendar

Отдельная система занятости и цен загородных домов для [domkazan116.ru](https://domkazan116.ru/). Каталог, описания и фотографии остаются на Tilda. Приложение не принимает оплату и не подтверждает бронирования автоматически.

## Запуск

Нужны Node.js 20.19+, 22.12+ или 24+ и PostgreSQL 16. Для локальной базы можно использовать Docker Compose.

1. `npm ci`
2. Скопируйте `.env.example` в `.env`. Замените демонстрационные значения. Для локального Docker разрешено оставить только пример `DATABASE_URL`; пароль в `compose.yaml` предназначен исключительно для разработки.
3. Укажите `ADMIN_EMAIL`, случайный `SESSION_SECRET` длиной не менее 32 символов и хеш пароля из `node scripts/hash-password.mjs` в `ADMIN_PASSWORD_HASH`. Не сохраняйте пароль в репозитории.
4. `docker compose up -d postgres` либо запустите собственный PostgreSQL.
5. `npm run db:deploy` и `npm run db:generate`.
6. `npm run dev`; админка доступна на `http://localhost:3000/admin`.

`.env` игнорируется Git. Для production нужны HTTPS, секреты в окружении сервера и регулярное резервное копирование базы. При локальной разработке новых миграций используйте `npm run db:migrate`.

## Модель и расчёт цены

`House` хранит только параметры для фильтрации: вместимость, район, число спален и санузлов, удобства, разрешение на животных, активность и ссылку на страницу Tilda. Описания и фотографии здесь не дублируются. У каждого дома есть уникальный `slug` для сопоставления с карточкой каталога и `revision` для защиты от перезаписи одновременных изменений.

Одна запись `BaseRate` содержит четыре цены за ночь в рублях для заданного периода: понедельник–четверг, пятница, суббота и воскресенье. `DateOverride` перекрывает цену отдельной ночи и сохраняется при изменении или удалении базового тарифа. `BlockedPeriod` закрывает даты; только заявка `BookingRequest` со статусом `CONFIRMED` исключает дом из поиска. Все интервалы полуоткрытые `[заезд, выезд)`, поэтому в день выезда дом снова свободен. Пересечение периодов тарифов и закрытий одного дома отклоняется ограничениями PostgreSQL `BaseRate_no_overlap` и `BlockedPeriod_no_overlap`.

## API и админка

`GET /api/availability?checkIn=2026-11-02&checkOut=2026-11-09&guests=4` возвращает свободные дома с итоговой ценой. Необязательные параметры: `district`, `bedrooms`, `amenities` (список через запятую), `petsAllowed=true`. Поиск принимает поездки от 1 до 60 ночей начиная с текущего дня в часовом поясе Москвы. CORS разрешён только для точного origin из `TILDA_ORIGIN`.

`POST /api/requests` принимает JSON с `houseId`, `checkIn`, `checkOut`, `guestCount`, `clientName`, обязательным `clientPhone`, необязательными `messenger` (`TELEGRAM`/`WHATSAPP`), `messengerContact`, `comment`, а также `consent: true` и случайным UUID `idempotencyKey`. Сервер повторно проверяет свободные даты и рассчитывает сумму из тарифов PostgreSQL. Цена и статус из браузера не принимаются. Повтор с тем же ключом возвращает ту же заявку без создания второй записи. Заявка остаётся новой и не закрывает даты. Ответ не содержит персональных данных клиента. Форма ограничена по размеру, использует скрытое антиспам-поле и лимиты на хешированные IP и телефон (15 минут). Для защиты от большого потока распределённого спама на публичном контуре дополнительно нужен WAF/CAPTCHA.

Новая заявка и запись Telegram-уведомления создаются в одной транзакции. `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` хранятся только в окружении сервера. Сообщение содержит ID заявки, дом, даты, гостей, рассчитанную сумму и контакты. Ошибка Telegram не показывается клиенту. Для повторной доставки настройте внешний планировщик на `POST /api/internal/telegram/retry` с заголовком `Authorization: Bearer <TELEGRAM_RETRY_SECRET>` (например, раз в минуту). Секрет должен содержать минимум 32 символа. Повторная доставка не создаёт новую заявку; при аварии между успешной отправкой Telegram и фиксацией результата возможно повторное сообщение с тем же ID заявки.

На `/admin/requests` доступны фильтры по дому и статусу, контакты, комментарий, изменение статуса и переход к периоду в шахматке. Подтверждение требует ручной проверки оплаты и повторной проверки дат; частичное exclusion-ограничение `BookingRequest_confirmed_no_overlap` в PostgreSQL запрещает двойную бронь. Отменить подтверждённую бронь можно только явным изменением её статуса. Действие «Открыть даты» в шахматке снимает только ручное закрытие.

Админка использует серверные сессии: в cookie хранится случайный токен, в PostgreSQL — только его SHA-256; сессия истекает через 8 часов и отзывается при выходе. Cookie имеет `HttpOnly`, `SameSite=Strict` и `Secure` на HTTPS. Вход ограничен пятью попытками за 15 минут для учётной записи и общим лимитом для запросов входа. Все маршруты `/api/admin/*`, кроме входа и выхода, проходят проверку сессии и Origin в `proxy.ts`; обработчики также вызывают общий `checkAdminApiAccess`.

Главная страница `/admin` показывает шахматку по месяцам: цены за ночь, ручные цены, закрытые дни и даты подтверждённых заявок. Две последовательные активации ячеек одного дома выбирают диапазон; также доступны поля дат для ввода с клавиатуры и перехода между месяцами. Действия «закрыть», «открыть», «изменить стоимость» и «убрать ручную цену» запрашивают подтверждение, сохраняются в транзакции и обновляют шахматку. «Открыть» снимает только ручное закрытие: подтверждённая заявка продолжает занимать дом. Массовое действие ограничено 366 ночами.

На `/admin/houses` можно добавить и изменить дом, включить или отключить его в поиске. Страница дома позволяет создать, изменить или удалить тарифный период с четырьмя ценами, заполнив ими календарь за выбранные даты. Дата окончания периода в интерфейсе включена, а в базе хранится как исключённая граница. Сервер проверяет поля и конфликты периодов. Каждый запрос изменения содержит текущую `revision`; при одновременной правке устаревший запрос получает HTTP 409 и пользователь должен обновить данные. Публичный поиск читает PostgreSQL при каждом запросе с `Cache-Control: no-store`, поэтому изменения доступны сразу после сохранения.

Для административной панели доступны `GET/POST /api/admin/calendar`, `POST /api/admin/houses`, `GET/PATCH /api/admin/houses/{houseId}`, `GET/POST /api/admin/houses/{houseId}/rates` и `PATCH/DELETE /api/admin/houses/{houseId}/rates/{rateId}`. API остаётся внутренним для админки.

## Каталог Tilda

Модуль `public/embed/domkazan-search.js` не создаёт собственные карточки. Он показывает форму поиска, а затем скрывает занятые карточки существующего каталога, оставляет свободные и обновляет их цены. Связь с базой идёт через уникальный `House.slug`; модуль не зависит от CSS-классов Tilda.

Для будущего подключения добавьте на обёртку каждой карточки стабильный атрибут `data-domkazan-house="slug-из-базы"`, а на элемент цены — `data-domkazan-price`. Добавьте отдельный контейнер формы и скрипт:

```html
<div data-domkazan-search data-api-url="https://calendar.example.invalid/api/availability" data-privacy-url="https://domkazan116.ru/actual-policy-page"></div>
<script src="https://calendar.example.invalid/embed/domkazan-search.js" defer></script>
```

Если редактор Tilda не позволяет добавить атрибуты к существующим карточкам, передайте модулю ссылки на DOM-элементы напрямую после их отрисовки:

```js
window.DomKazanCalendar.mount({
  root: document.getElementById("calendar-search"),
  apiUrl: "https://calendar.example.invalid/api/availability",
  cards: [
    { slug: "house-slug", element: document.getElementById("stable-card-id"), priceElement: document.getElementById("stable-price-id") },
  ],
  // Опционально: значения существующих фильтров каталога.
  getFilters: () => ({ district: "Лаишевский", amenities: "sauna,wifi" }),
  privacyUrl: "https://domkazan116.ru/actual-policy-page",
});
```

Модуль добавляет к свободным карточкам кнопку заявки; форма открывается в отдельном Shadow DOM, сохраняет выбранные дом/даты/число гостей, запрашивает согласие и после отправки показывает ссылки связи из `PUBLIC_OWNER_PHONE`, `PUBLIC_OWNER_TELEGRAM`, `PUBLIC_OWNER_WHATSAPP`. Без действительной HTTPS-ссылки на политику обработки данных форма заявки недоступна. Модуль возвращает метод `reset()`, который восстанавливает исходную видимость и текст цен. При изменении DOM Tilda модуль можно смонтировать заново с актуальными ссылками на карточки. Встраивание в действующий сайт этим PR не выполняется.

## Проверки

`npm run typecheck`, `npm run lint`, `npm test`, `npm run build`, `npm audit`.

Для PostgreSQL-интеграции: `docker compose up -d postgres-test`, затем `npm run test:integration`. Скрипт требует отдельный `TEST_DATABASE_URL` с именем базы, заканчивающимся на `_test`, применяет миграции и запускает тесты без производственных данных. Используются только синтетические записи.

## Следующие этапы

Для запуска на реальном сайте нужно сопоставить карточки Tilda с `slug` домов, указать действительную политику обработки данных, контакты владельца, Telegram-секреты и планировщик повторной доставки. Также требуется установить срок хранения и порядок удаления персональных данных согласно применимым требованиям. Эти значения не включены в репозиторий. Онлайн-оплата и автоматическое подтверждение не предусмотрены.
